## المرحلة 0 — شبكة الأمان

تأتي أولاً حتى تحمي الاختبارات كل إصلاح لاحق.

- تثبيت Node 22 عبر `.nvmrc` وحقل `engines`، وحل تعارض `localStorage` مع jsdom.
- تفعيل ESLint فعلياً بدل `echo "ok"`.
- إزالة `allow_failure` من `lint_typecheck`، وإضافة بناء اللوحة إلى CI.
- تحويل `scoreFromIssues` إلى دالة مُصدَّرة يستوردها الاختبار بدل نسخها.
- إعداد Playwright مع أول اختبار دخان: اللوحة مخفية عند التحميل، وتفتح وتُغلق.
- عزل إنشاء تطبيق Hono عن `serve()` حتى تُختبر مسارات الـ API مباشرة.

**معيار الإنجاز:** CI إلزامي وأخضر، واختبار الدخان يفشل على الكود الحالي بسبب P0-01.

## المرحلة 2 — الأمان وسلامة الرخص

**الودجت والرخص**
- P0-05: عند ضبط `siteKey` لا يُركَّب الودجت دون إعداد بعيد أو مخزن صالح، ويتوقف صراحة عند 403 و404.
- P0-06: فحص `expiresAt`، ومقارنة Origin بقائمة `domains`، وتطبيع النطاق عند الإنشاء وترحيل القيم الموجودة.

**الإعدادات**
- P0-07: ألوان hex فقط، ونمط صارم لـ `widgetWidth`، وروابط https فقط، مع إعادة التحقق عند القراءة.
- P1-20: حذف `PUT /config` القديم والتحقق من الإعدادات عند النشر.

**الماسح**
- P0-08: حل DNS والتحقق من IP لكل طلب، بما فيها التحويلات، وحصر الفحص بنطاق الموقع.
- نقل التشغيل إلى Worker معزول الشبكة في المرحلة 4 ضمن P1-17 إن تعذر إنجازه هنا. لا يُفتح الماسح لعملاء حقيقيين قبل اكتمال العزل.

**الهوية والجلسات**
- P0-09: حذف القيم الافتراضية من صفحة الدخول، وخطأ إقلاع عند غياب كلمة المرور الأولية في الإنتاج، وتغييرها إلزامياً عند أول دخول.
- P0-10: التحقق من `next` عبر `new URL` ومطابقة الأصل.
- P0-11: IP من الاتصال أو وكيل موثوق، وحد لكل حساب، ومخزن مشترك.
- P1-18: جلسات قابلة للإبطال، وكوكي HttpOnly فقط، وإزالة الرمز من `localStorage`.
- P2-09: تحقق وهمي لتوحيد زمن الدخول.

**سطح الهجوم**
- P1-19: قائمة أحداث مسموحة، وحدود طول، و`bodyLimit`، وإدخال دفعي.
- P1-21: رؤوس الأمان، وحدود طول المدخلات، وإثبات ملكية النطاق عبر DNS أو meta tag.

**معيار الإنجاز:** كل سيناريو هجوم في تقرير الجودة مكتوب كاختبار API ويُرفض. مراجعة أمنية مستقلة قبل الانتقال للمرحلة 5.

## المرحلة 3 — جودة الودجت

**الخصائص (P0-12)**
- التباين: ثيم ألوان فعلي بدل `filter`، مع تحقق من نسب التباين.
- تكبير النص: تكبير نسبي لا يقلل أي حجم قائم.
- ارتفاع السطر: قيم بلا وحدة، وأقصى قيمة أقل من `4em` الحالية.
- إيقاف الحركة: `animation-play-state: paused` بدل `animation:none`.
- دليل القراءة (P1-04): مستمع واحد قابل للإزالة ودعم اللمس.

**السلوك**
- P1-02: تنظيف الأصناف والعناصر عند `teardown`، وإعادة التركيب في SPA، وتطبيع المسارات.
- P1-03: حفظ قرار الإيقاف صراحة.
- P1-08: حماية `sessionStorage`.
- P2-02: حذف الإعدادات غير العاملة، وحفظ اللغة، وتوريث موضع الجوال.
- P2-04: إصلاح واجهة `init` العامة.

**الوصول والعرض**
- P1-06: حلقة تركيز مزدوجة اللون، وتباين المفتاح والشارة والنص الثانوي، وأسماء أزرار كاملة، وتحسين حبس التركيز.
- P1-07: رأس وتذييل ثابتان وقائمة قابلة للتمرير.
- P2-03: قرار الخط أدناه.

**معيار الإنجاز:** axe نظيف على الودجت، واختبار كل خاصية على صفحات عربية وإنجليزية ومختلطة دون قص أو تراكب.

## قرارات مطلوبة

1. **خط الودجت (قبل المرحلة 3):** التوصية استخدام خط النظام في الودجت، لأنه أخف ولا يرسل طلبات إلى طرف ثالث من مواقع العملاء. البديل ملف subset مستضاف ذاتياً.
2. **سلوك تعطل الـ API (قبل المرحلة 2):** التوصية عدم ظهور الودجت دون إعداد موثوق، ليعمل الإيقاف الطارئ دائماً. العيب أن تعطل الـ API يخفي الودجت عن زوار جدد لم يخزنوا الإعدادات، لذا يلزم توفر عالٍ أو ملف إعدادات عبر CDN.
3. **طريقة إثبات النطاق (قبل المرحلة 2):** التوصية سجل DNS TXT مع meta tag كبديل.
4. **المخزن المشترك لتحديد المعدل (قبل المرحلة 2):** التوصية Redis، ويمكن البدء بجدول في PostgreSQL إذا سبق الانتقال إليه.
